ДОКУМЕНТАЦИЯ UI/UX

1. Введение и цели
Назначение: Дашборд преподавателя — это центральный хаб (главная страница) после авторизации. Он предназначен для быстрого обзора текущих задач, расписания, успеваемости студентов и важных уведомлений.
Целевая аудитория: Преподаватели, кураторы курсов, репетиторы.
Ключевые задачи интерфейса:

    Снизить когнитивную нагрузку (показывать только то, что требует внимания сейчас).
    Обеспечить быстрый доступ к расписанию и непроверенным работам.
    Дать сводную аналитику по группам/студентам.

2. Глобальная структура (Layout)
Макет состоит из трех основных зон:
2.1. Левый Сайдбар (Навигация)

    Логотип и название платформы.
    Меню навигации:
        🏠 Главная (Дашборд) — активный по умолчанию.
        📅 Расписание.
        👥 Мои студенты / Группы.
        📝 Задания и проверки.
        📚 Библиотека материалов.
        📊 Аналитика.
        ⚙️ Настройки.
    Кнопка выхода (Logout) в нижней части сайдбара.
    Поведение: На десктопе всегда развернут. На планшетах/мобильных сворачивается в иконки или скрывается за «бургер-меню».

2.2. Верхний Хедер (Header)

    Поиск (Глобальный): Поиск по студентам, группам, материалам.
    Уведомления (Колокольчик): Бейдж с количеством непрочитанных. При клике — выпадающий список (комментарии студентов, системные алерты).
    Профиль пользователя: Аватар, Имя Фамилия, роль. При клике — выпадающее меню (Профиль, Смена пароля, Выход).

2.3. Основная область (Main Content)
Сетка (Grid) из виджетов. Адаптируется под размер экрана (от 3 колонок на десктопе до 1 на мобильном).
3. Детализация виджетов (Блоки дашборда)
Виджет 1: «Расписание на сегодня / Ближайшие пары»

    Описание: Список предстоящих занятий на текущий день.
    Элементы строки:
        Время начала и окончания (например, 10:00 - 11:30).
        Название дисциплины / группы.
        Формат (Онлайн / Офлайн + номер аудитории).
        Кнопка действия: «Подключиться» (для Zoom/Meet) или «Начать урок».
    Состояния:
        Активная пара: Подсвечивается акцентным цветом, кнопка «Подключиться» активна.
        Будущая пара: Серый текст, таймер до начала.
        Завершенная пара: Зачеркнутый текст или приглушенный цвет.
    Пустое состояние: Иллюстрация + текст «На сегодня пар нет, отличный день для проверки работ!».

Виджет 2: «Требует внимания» (Задачи и Дедлайны)

    Описание: Карточки с задачами, которые нужно выполнить преподавателю в приоритете.
    Элементы:
        Иконка типа задачи (Проверка ДЗ, Ответ студенту, Заполнение журнала).
        Текст: «Проверить работы группы ИТ-21 (12 из 25)».
        Индикатор срочности (Красный бейдж «Дедлайн сегодня», Желтый «Завтра»).
    Кликабельность: Клик по карточке ведет на соответствующий раздел (в журнал оценок или в чат).

Виджет 3: «Сводка по успеваемости / Аналитика»

    Описание: Краткий график или цифры по активным группам.
    Элементы:
        Выпадающий список выбора группы.
        Показатели: Средняя посещаемость (%), Средний балл, Количество задолжников.
        Мини-график (Sparkline) динамики за последние 2 недели.
    Взаимодействие: Клик по виджету ведет в полный раздел «Аналитика».

Виджет 4: «Лента активности / Уведомления»

    Описание: Последние действия студентов или системные новости.
    Примеры событий:
        Иван Иванов сдал лабораторную работу «Физика». (2 мин назад)
        Мария Петрова задала вопрос в чате группы. (15 мин назад)
    Кнопка: «Показать все» (ведет в общий центр уведомлений).

4. Состояния интерфейса (States)
Для корректной работы фронтенда и QA необходимо предусмотреть следующие состояния:

    Загрузка (Loading / Skeleton):
        Пока данные тянутся с API, вместо виджетов отображаются «скелетоны» (серые пульсирующие плейсхолдеры в форме блоков).
    Пустые состояния (Empty States):
        Если у преподавателя нет групп: «У вас пока нет назначенных групп. Обратитесь к администратору».
        Если нет задач на проверку: «Все работы проверены! 🎉».
    Ошибки (Error States):
        Если API вернул ошибку 500/404: Блок виджета заменяется на плашку «Не удалось загрузить расписание. [Попробовать снова]».
    Ограничение данных (Overflow):
        Если в виджете «Расписание» больше 4 пар, первые 3 показываются, а внизу кнопка «Показать все (еще 5)».

5. Интерактивность и переходы (Interactions)

    Hover-эффекты: Все кликабельные карточки и кнопки имеют состояние наведения (изменение фона, появление тени, изменение цвета иконки).
    Модальные окна (Quick View):
        При клике на «Сдать работу» в виджете задач может открываться модальное окно с предпросмотром файла студента, чтобы преподаватель мог проверить его, не уходя с дашборда.
    Drag & Drop: (Если применимо) Возможность менять порядок виджетов на дашборде под себя.

6. Адаптивность (Responsive Breakpoints)

    Desktop (1440px и шире): 3 колонки виджетов. Сайдбар развернут (ширина 240px).
    Laptop (1024px - 1439px): 2 колонки виджетов. Сайдбар развернут. (ПОКА НЕ НАДО ДЕЛАТЬ)

7. Дизайн-токены и UI Kit
(Здесь указываются ссылки на глобальные стили, чтобы разработчики не использовали "магические числа")

    Цвета статусов:
        Успех / Сдано: #10B981 (Зеленый)
        Внимание / Дедлайн скоро: #F59E0B (Оранжевый)
        Ошибка / Просрочено: #EF4444 (Красный)
        Информация / Онлайн: #3B82F6 (Синий)
    Типографика: Inter / Roboto. Заголовки виджетов — H3 (18px, SemiBold), основной текст — Body (14px, Regular).
    Отступы: Базовая сетка 8px. Внутренние отступы виджетов 24px. Расстояние между виджетами 16px или 24px.

8. Требования к API (Для Backend-разработчиков)
Для отображения дашборда фронтенду потребуется следующий эндпоинт (или набор эндпоинтов):

    GET /api/v1/teacher/dashboard/summary
        Ответ должен включать:
            schedule_today: [массив объектов пар]
            pending_tasks: [массив объектов задач с дедлайнами]
            notifications: [последние 5 уведомлений]
            analytics_brief: { avg_attendance, avg_grade }

9. Доступность (Accessibility / a11y)

    Все иконки без текста должны иметь aria-label или скрытый текст для скринридеров.
    Управление дашбордом должно быть полностью доступно с клавиатуры (Tab-навигация по карточкам и кнопкам).
    Цвет не должен быть единственным способом передачи информации (например, рядом с красным цветом "Просрочено" обязательно должен быть текст или иконка).
    Контрастность текста и фона должна соответствовать стандарту WCAG 2.1 AA (минимум 4.5:1 для обычного текста).
