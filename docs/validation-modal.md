ДОКУМЕНТАЦИЯ UX/UI: СИСТЕМНЫЕ МОДАЛЬНЫЕ ОКНА ВАЛИДАЦИИ ФОРМ

Документация: Модальное окно ошибок валидации

1. Назначение
Блокирующее модальное окно, которое появляется при попытке сохранить форму с ошибками. Показывает все ошибки сразу и помогает быстро перейти к проблемным полям.
Когда появляется:

    Нажатие «Сохранить» при незаполненных обязательных полях.
    Ошибка формата (email, телефон, дата).
    Логическая ошибка (дата окончания < даты начала).
    Ответ сервера 400 / 422.

2. Структура окна

* Шапка

    Иконка ⚠️ (желтая) или ❌ (красная для системных ошибок).
    Заголовок: «Не удалось сохранить данные» или «Проверьте правильность заполнения».
    Крестик закрытия в углу.

* Тело — список ошибок
Каждый пункт:

    Иконка типа ошибки.
    Название поля — описание проблемы.
    Ссылка [Перейти к полю].

Пример:

    ⚠️ Дата начала — не может быть раньше сегодня (18.11.2026). [Перейти →]

Если ошибок больше 5 — список скроллится (макс. высота 400px).

* Футер

    Кнопка «Понятно» (закрывает окно, форма остается с подсвеченными полями).
    Или «Исправить все» (закрывает окно и переходит к первому проблемному полю).

* Оверлей
Затемнение rgba(0,0,0,0.5) + blur 4px. Клик по фону не закрывает окно.

3. Поведение

* Открытие:

    Анимация: fade-in + scale 0.95→1.0 за 200мс.
    Фокус — на первую кнопку.
    Скролл страницы блокируется.

* Закрытие:

    По кнопке «Понятно».
    По клавише Esc.
    После закрытия проблемные поля остаются подсвеченными красным с inline-ошибками.

* Переход к полю (по клику на ссылку):

    Модалка закрывается.
    Страница скроллится к полю (smooth).
    Поле подсвечивается рамкой (pulse 2 раза).
    Курсор фокусируется в поле.

4. Стили (кратко)

    Цвет предупреждения: #F59E0B
    Цвет критической ошибки: #EF4444
    Ширина модалки: макс. 480px, скругление 12px.
    Тень: 0 20px 25px rgba(0,0,0,0.1).
    Заголовок: 18px SemiBold. Текст ошибки: 14px Regular.
    На мобильных (до 768px) — открывается снизу как bottom sheet.

5. Формат ответа от API

json
{
  "status": 422,
  "error": "VALIDATION_FAILED",
  "message": "Не удалось сохранить данные",
  "errors": [
    {
      "field": "start_date",
      "label": "Дата начала",
      "code": "DATE_IN_PAST",
      "message": "не может быть раньше сегодня (18.11.2026)",
      "type": "logical"
    },
    {
      "field": "email",
      "label": "Email",
      "code": "INVALID_FORMAT",
      "message": "неверный формат",
      "type": "format"
    }
  ]
}

Типы ошибок (type): required | format | logical | conflict — для подбора иконки.

6. Доступность

    role="alertdialog", aria-modal="true".
    Focus trap: Tab не уходит за пределы модалки.
    Esc закрывает окно.
    Скринридер зачитывает заголовок и первую ошибку.
    Контраст текста ≥ 4.5:1. Рядом с красной рамкой — иконка или текст (не только цвет).

7. Чек-лист для QA

    * Модалка открывается при ошибке валидации.
    * Список ошибок соответствует форме.
    * Ссылка «Перейти к полю» скроллит и фокусирует поле.
    * После закрытия поля остаются подсвеченными красным.
    * Inline-ошибки отображаются под полями.
    * Повторный сабмит показывает только оставшиеся ошибки.
    * Esc закрывает окно.
    * Focus trap работает.
    * На мобильном — bottom sheet.
    * При ошибке 500 — общий текст, без списка полей.
